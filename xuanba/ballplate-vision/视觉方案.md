# 简易滚球系统 · 视觉方案（树莓派 + USB 摄像头）

> 对应赛题：2027 国赛测控方向 A 组训练题 1 —— 简易滚球系统
> 本方案只负责「视觉」这一部分：用树莓派 + USB 摄像头实时检测小球位置、识别图纸上涂黑的九宫格轨迹，并把结果通过串口发给 STM32 控制板。平板倾斜控制（PID、舵机云台、驱动）由 STM32 完成，不在本文范围内。

---

## 1. 任务回顾与视觉要解决的两件事

赛题要求小球（直径 ≤ 2.5 cm）在一块 30 cm × 30 cm 的光滑平板上按指定路线滚动、在指定方格内停留。平板被均分成 9 个 10 cm × 10 cm 的小方格，编号如下（这是从题目要求反推出的布局，请与「图 1 平板俯视图」核对）：

```
+-------+-------+-------+
|   1   |   2   |   3   |
+-------+-------+-------+
|   4   |   5   |   6   |
+-------+-------+-------+
|   7   |   8   |   9   |
+-------+-------+-------+
```

视觉系统需要完成两件事：

1. **实时小球定位**：摄像头俯视拍摄平板，识别小球在图像中的位置，换算成平板上的物理坐标（毫米）以及小球当前所在的方格编号，实时发给 STM32 用于闭环控制。
2. **轨迹识别（发挥部分）**：读入一张画有九宫格的图纸，图纸上某些方格被涂黑表示运动路线，识别出被涂黑的方格编号序列，作为本次动作的目标路线。

## 2. 总体架构

```
                 USB 摄像头（俯视安装在平板正上方）
                              │  USB 视频流
                              ▼
        ┌─────────────────────────────────────┐
        │             树莓派（视觉）              │
        │  · 图像采集（OpenCV / V4L2）           │
        │  · 小球检测（HSV 颜色分割）             │
        │  · 像素坐标 → 毫米坐标（透视变换）       │
        │  · 九宫格判定                          │
        │  · 图纸涂黑轨迹识别（发挥部分）          │
        └──────────────────┬──────────────────┘
                           │ 串口 UART（坐标 / 轨迹）
                           ▼
        ┌─────────────────────────────────────┐
        │             STM32（控制）             │
        │  · PID 闭环                          │
        │  · 舵机 / 步进驱动平板倾斜             │
        └─────────────────────────────────────┘
```

为什么采用「树莓派视觉 + STM32 控制」的分工：视觉是计算密集任务（每秒几十帧图像处理），放在带 Linux 和 OpenCV 的树莓派上开发调试效率最高；而电机/PWM 实时控制对时序要求高，STM32 更合适。两者用一根串口线解耦，职责清晰，也方便你复用已有的 STM32 经验。

## 3. 硬件选型

**树莓派**

- 推荐 Raspberry Pi 4B（4GB）或 Pi 5。Pi 3B+ 也能跑 640×480 的 HSV 检测，但帧率余量小。
- 系统：Raspberry Pi OS（Bookworm，64 位）。
- 依赖：`opencv-python`、`numpy`、`pyserial`。

**USB 摄像头**（关键，直接影响检测稳定性）

- 普通免驱 UVC 摄像头（720p/1080p）即可，不必上工业相机。
- 三点硬性要求：
  1. **固定焦距**（无自动对焦，或能锁定对焦）。自动对焦会导致画面放大倍数来回变，破坏坐标标定。
  2. **能关闭自动曝光和自动白平衡**。这两项自动调节会让颜色和亮度漂移，HSV 阈值就失效了。优先选能在 V4L2 里手动锁参数的摄像头。
  3. **视场刚好覆盖 30 cm 平板再加一点余量**。视场过大（超广角）畸变严重，透视校正误差大；视场刚好盖住平板最理想。
- 分辨率用 640×480 或 1280×720 即可，不必 1080p。640×480 下 2.5 cm 的小球大约占 50 像素，足够稳定。

**安装与光照**（比算法更能决定成败）

- 摄像头固定在平板正上方，光轴尽量垂直于平板，拍摄范围能完整看到平板四角。
- 用漫射光均匀照明（LED 灯板或加柔光纸），避免点光源阴影和反光；小球和高反光平板要避开镜面反射。
- 摄像头支架要牢固，标定完成后再去动摄像头，坐标就全偏了。

## 4. 坐标系统与相机标定（透视变换）

### 4.1 坐标定义

- 平板左上角为原点，x 向右、y 向下，单位毫米，范围 0～300。
- 方格编号 `n`（1～9）与坐标的关系：

```
列 col = (n - 1) % 3，行 row = (n - 1) // 3
方格中心：x = col*100 + 50，y = row*100 + 50（mm）
判定小球在方格 n 内：col*100 ≤ x < (col+1)*100 且 row*100 ≤ y < (row+1)*100
```

### 4.2 为什么要标定

摄像头是倾斜或带透视地看平板的，图像里的像素坐标和平板上的真实毫米坐标不是线性对应。需要求一个**单应矩阵 H**，把任意像素点 (u, v) 映射到平板毫米坐标 (x, y)。平板是平面，一个 3×3 的单应矩阵就能精确描述这个映射。

### 4.3 标定流程（本方案用鼠标点击四角）

1. 放好平板、固定摄像头，运行 `calibrate.py`。
2. 在画面里按「左上 → 右上 → 右下 → 左下」顺序点击平板四个角。
3. 程序用 `cv2.findHomography` 计算 H 并保存到 `calibrate.npz`。
4. 之后运行时用 `cv2.perspectiveTransform` 把球心像素坐标换算成毫米坐标。

进阶：如果以后想自动标定，可以在平板四角贴 4 个 ArUco 码，用 `cv2.aruco` 自动检测角点，避免手动点击的人为误差。当前方案先用鼠标点击，简单可靠。

## 5. 小球检测（HSV 颜色分割）

### 5.1 为什么选颜色分割

竞赛现场光照可控，只要把「小球颜色」和「平板颜色 + 背景」做成高对比（例如红色小球 + 白色平板，或绿色球 + 浅灰板），用 HSV 阈值把小球像素单独切出来是最快、最稳的方案，树莓派上能轻松跑到 30 fps 以上，且几乎不受小球形状、反光角度影响（比霍夫圆检测稳）。

### 5.2 处理流程

```
BGR 帧 → 转 HSV → inRange 阈值分割 → 开/闭运算去噪
      → findContours 找轮廓 → 取面积最大轮廓
      → 用图像矩(moments)求质心 → 球心像素坐标 (cx, cy)
```

每一步的要点：

- **HSV 阈值**：`cv2.inRange(hsv, lower, upper)`。红色在 HSV 里 H 值横跨 0 和 179 两端，用单段 `inRange` 可能漏掉一部分，需要时可以对两段区间分别 `inRange` 再取并集（代码里已预留，见 `ball_detector.py` 注释）。
- **形态学**：先开运算去掉孤立噪点，再闭运算填掉球内部的反光小洞。
- **轮廓筛选**：取面积最大的轮廓作为小球，用面积上下限过滤掉远处的小色块和大面积干扰。
- **质心**：用 `cv2.moments` 的一阶矩除以零阶矩得到质心，比外接矩形中心更准。
- **可选平滑**：对连续帧的球心做指数移动平均（EMA），抑制抖动，让 STM32 收到的坐标更平缓。

### 5.3 现场调参

提供 `hsv_tuner.py`：打开摄像头实时显示原图、二值掩码，用滑条拖 HSV 上下限，直到画面里只有小球是白色、其余全黑。把最终数值填回 `config.py`。

## 6. 九宫格判定

球心毫米坐标 (x, y) 到手后，用第 4.1 节的公式直接算出所在方格编号。这一格编号就是「小球当前所在位置」，STM32 据此判断是否进入指定方格、是否停留足够时间。

---

## 7. 图纸涂黑九宫格轨迹识别（发挥部分）

### 7.1 要识别什么

发挥部分要求「识别图纸上设定的小球运动路线（最多 3 个，进阶最多 5 个小正方形）」。图纸是一张画有 3×3 网格的纸，路线通过**把某些方格涂黑**来表示。视觉要输出这些被涂黑方格的编号序列。

### 7.2 处理流程

```
读入图纸图片 → 灰度化 → 高斯模糊 → Otsu 反相阈值（深色变白）
      → 找最大轮廓 = 九宫格外框 → approxPolyDP 取四角 → 透视矫正成 300×300
      → 均分 9 格 → 每格中心区算「涂黑像素占比」 → 超过阈值判为涂黑
      → 输出编号序列
```

关键点：

- 用「每格中心 70% 区域」的黑色占比来判断，而不是整格，这样能避开网格线本身的干扰。
- 阈值默认 0.4（中心区黑色像素占比超过 40% 判定涂黑），可在 `config.ROUTE_FILL_THRESHOLD` 调整。
- 网格外框要画得清晰完整（外框闭合），程序靠外框四角做透视矫正。

### 7.3 关于路线顺序（重要，需你确认）

只「涂黑」方格本身不携带先后顺序信息。本方案做了两件事：

1. 默认按方格编号升序输出被涂黑格（`1→2→…→9` 阅读顺序）。
2. 预留了**起始标记检测**：如果被涂黑格的中心留有一个小白点/小圆圈，程序会把它识别为起点，把该格排到序列最前。

如果你们赛题的图纸用**数字**或**箭头**标注顺序，请告诉我，我可以再加：白色数字 OCR（识别 1/2/3…顺序）、或箭头方向检测。

## 8. 与 STM32 的串口通信协议

树莓派通过板载 UART（`/dev/ttyAMA0`）或 USB 转串口（`/dev/ttyUSB0`）连接 STM32，波特率 115200，文本行协议，每行以 `\n` 结尾：

- **小球位置**（实时）：`X:123.4,Y:234.5,C:8\n`
  - X、Y 为毫米坐标，C 为方格编号（1～9）。
- **目标轨迹**（识别图纸后一次性下发）：`R:6,9,8\n`
  - 逗号分隔的方格编号序列。

STM32 侧按行解析即可。协议简单、可读、易调试（可用串口助手直接观察）。如需更紧凑的二进制协议（帧头 + 长度 + 校验），可以再改。

## 9. 软件部署与运行步骤

在树莓派上：

```bash
sudo apt update && sudo apt install -y python3-opencv python3-pyserial
# 或 pip install opencv-python numpy pyserial

# 1. 现场标定小球颜色（HSV）
python3 hsv_tuner.py          # 拖动滑条，把数值填进 config.py

# 2. 标定相机（点击平板四角）
python3 calibrate.py          # 生成 calibrate.npz

# 3. 测试轨迹识别（可选）
python3 route_reader.py 图纸照片.jpg

# 4. 运行主流程（检测球 + 串口下发）
python3 main.py
```

接线：树莓派 GND 与 STM32 共地，TX/RX 交叉连接（树莓派 TX → STM32 RX，树莓派 RX → STM32 TX，若 STM32 是 5V 逻辑电平注意电平匹配）。未接 STM32 时把 `config.ENABLE_SERIAL` 设为 `False`，`main.py` 仍能在屏幕上显示检测结果，方便先调视觉。

## 10. 性能与抗干扰要点

- **帧率**：640×480 下 HSV 分割 + 轮廓 + 透视变换，Pi 4B 上可到 30+ fps，完全满足赛题「秒级停留/行进」的要求。
- **光照稳定**：锁定曝光和白平衡后，HSV 阈值基本不再需要现场改。照明务必均匀、无直射反光。
- **反光处理**：小球选哑光材质（赛题要求坚硬均匀），平板避免镜面。
- **抖动平滑**：坐标加 EMA 滤波后下发给 STM32，避免 PID 被高频噪声干扰。
- **丢失保护**：小球被短暂遮挡或检测失败时，`ball_detector` 返回「未找到」，`main.py` 停发该帧（或补发上一帧坐标），不让 STM32 收到垃圾坐标。
- **标定失效**：一旦摄像头或平板位置动了，必须重新跑 `calibrate.py`。
